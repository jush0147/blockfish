# S37　依已知終局分數安排搜尋佇列

S36 更換整棵樹的引導估值後，完整賽事未能取得穩定改善。S37 改測一個可直接驗證的排序問題。B* 對尚待處理的節點依 f 排序，對已完成路徑卻用 f 加父節點 f 回傳，在特殊的底行目標則用步數。既然終局分數已知，搜尋可以直接用這個值決定何時取出終局，回到各層選下一個展開節點。非終局排序使用 2f 以對齊單位。特徵、四終局回傳、落點枚舉與生成節點計費均沿用 cheese-robust。這個方法只增加終局判斷與整數運算，也不需要把舊搜尋器挑中的節點當訓練答案。它仍沿用現有終局評分與既有底行目標，因此對中盤補垃圾後的價值可能仍有偏差。

## 六塊內完賽的公開路徑

在 32 局舊開發資料各取兩個事前約定的尾盤，所有垃圾均已生成。模型只取得目前盤面、Hold 與五顆預覽，每個盤面上限 50,000 生成節點。每個已評分首步輸出一條完整路徑。用原遊戲模擬器從公開狀態重建兩個指定的條件世界，逐一驗證動作，最多六塊。只有實際清完剩餘垃圾才算成功。後續抽樣的方塊不送入搜尋；所有取樣盤面都有 Hold，檢查範圍內不需要鎖定未見方塊。來源軌跡雜湊已與 S34 完整回放稽核核對。

| 策略 | 受測路徑 | 可完賽的首步 | 可完賽盤面 | 首選路徑完賽盤面 | 篩選程序 CPU 秒 |
|---|---:|---:|---:|---:|---:|

兩側均無無效操作。四個盤面各多出 2、3、1、1 個成功首步，其餘 60 盤的成功首步數相同。29 個有解盤面逐一對照，最短已找到的完賽步數全部相同。在 64 個樣本上找到更多完賽路徑，效益集中於已有解的盤面。符合事前路徑門檻，啟用 78100..78111 未見開發賽事。路徑樣本僅來自 32 局，且只檢查決策層輸出的計畫。

## 重現

從專案根目錄執行：

```sh
source /workspace/.blockfish-env/activate.sh
bash research/build_s37.sh
python3 research/s37_paths.py
python3 research/bench.py --binaries research/bin/learned-robust research/bin/robust-terminal-priority --configs 50/5,10,10,10 --start 78100 --count 12 --jobs 4 --timeout 600 --out research/results/s37-dev.jsonl
python3 research/replay_audit.py research/results/s37-dev.jsonl --out research/results/s37-dev-replay.json
python3 research/s37_summary.py dev
```

固定協定見 S37_PROTOCOL.md；兩個路徑 JSON 保留每個輸出操作、消行序列、是否完賽與節點用量。控制探針與候選使用相同建置設定，完整對局控制使用 S11 凍結執行檔。引擎 66 項測試全部通過。
