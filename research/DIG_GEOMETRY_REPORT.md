# S32　洞口周圍的盤面估值

回顧 S1～S31，兩項有獨立對局支持的改進是從遊戲資料學習盤面成本，以及 S11 用數個不同終局支持同一第一步。S1～S10 的更早回傳、beam、根分支覆蓋、殘局與權重選擇都顯示搜尋量及預測誤差難以單獨解釋完整對局表現。S12～S19 改動搜尋邊界、第二步多樣性及七袋推論；有些勝過實作對照，對既有最佳版的優勢卻未通過獨立確認。S20～S23 的 Hold 修正只有很小的預測變化。S24～S31 的展開分配、重複狀態合併、全域搜尋、短期模擬與跨步計畫重用也未取得足以升級的結果。S31 正式盤面只用於回顧結論。

S32 測試特徵表示的缺口。凍結估值包含高度、井、轉換數及 residue-based piece estimate。不同的堆疊可以有近似的全盤統計，卻須經過不同數量的落子才能接觸垃圾洞。候選從底部連續單缺格行辨認最上層洞口，再測其上方占用格數、占用垂直跨度、兩側較低及較高的堆疊高度（截至四格）、是否靠牆，以及與下一洞的水平距離。此辨認只用占用格，因此玩家堆成的單缺格行也可能被納入。B*、SRS、Hold、當前塊加五預覽及 robust4 回傳均沿用原實作。

訓練使用 S26 observer 的 32 局開發軌跡，合計 6,118 對相隔七次落子的觀察。以凍結估值和既有垃圾價格計算剩餘成本殘差，擬合殘差差值至兩盤面特徵的差值。這會消去同一局共同的最終方塊數。每局等權、固定 ridge 4、零截距。六個權重可正可負。原有的訓練策略分布、七步走法及幾何辨認誤差都可能影響部署結果。訓練樣本彼此相關，品質判斷採新種子的完整 100L 對局。

固定兩個執行檔，在 77200..77223 交錯各跑 24 局，每步上限 50,000 個生成節點，垃圾 9/4，無時間截止，並記錄 CPU 與峰值 RSS。兩版須全部完成且候選平均較低才開啟 77300..77363 最終 64 對。升級門檻為全部完成且候選減基準的配對 bootstrap 95% 區間上限小於零。實驗規則見 PROTOCOL.md。

重現時在專案根目錄執行以下指令。已鎖定的結果可由 lock 與 decide_cohort.py 重新核算。

```sh
source /workspace/.blockfish-env/activate.sh
python3 research/fit_dig_geometry.py
python3 research/build.py robust-dig-geometry
python3 research/run_s32.py
```
